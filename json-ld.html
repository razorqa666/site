JSON-LD — формат структурированных данных

JSON for Linked Data — рекомендованный Google способ добавить структурированные данные на страницу.

Что такое JSON-LD

JSON-LD (JSON for Linking Data) — это формат сериализации связанных данных на основе JSON, ставший официальной рекомендацией W3C в 2014 году. В отличие от Microdata и RDFa, JSON-LD вставляется в отдельный тег <script> и не требует изменений в структуре HTML-разметки страницы.

Официальная позиция Google: «Мы рекомендуем JSON-LD для реализации структурированных данных везде, где это возможно.» — документация Google Search Central, 2024.

Ключевые ключевые слова JSON-LD

Ключевое словоНазначениеПример значения
@contextОпределяет словарь (пространство имён)"https://schema.org"
@typeУказывает тип сущности"Article", "Product"
@idУникальный идентификатор (URI)"https://example.com/page"
@graphМассив нескольких сущностей в одном блоке[{...}, {...}]
@languageЯзык текстовых значений по умолчанию"ru"
@valueЛитеральное значение с типом или языком{"@value": "Привет", "@language": "ru"}

Структура документа JSON-LD

Минимальная структура
<script type="application/ld+json">
{
  "@context": "https://schema.org",  // обязательно
  "@type": "Article",              // тип сущности
  "headline": "Заголовок статьи",  // свойства типа
  "author": {
    "@type": "Person",
    "name": "Имя Автора"
  },
  "datePublished": "2026-09-01"  // ISO 8601
}
</script>

Граф данных @graph

Когда на одной странице нужно разметить несколько независимых сущностей (например, организацию и хлебные крошки одновременно), используется массив @graph:

{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "WebSite",
      "@id": "https://example.com/#website",
      "name": "Мой сайт",
      "url": "https://example.com"
    },
    {
      "@type": "BreadcrumbList",
      "itemListElement": [
        {
          "@type": "ListItem",
          "position": 1,
          "name": "Главная",
          "item": "https://example.com"
        }
      ]
    }
  ]
}

Преимущества JSON-LD перед другими форматами

  • Не затрагивает видимую HTML-разметку — проще внедрять и поддерживать
  • Легко добавить через CMS или систему управления тегами (GTM)
  • Можно генерировать динамически на сервере (Node.js, PHP, Python)
  • Легко читается и понимается разработчиками
  • Единственный формат, где Google официально рекомендует использование
  • Поддерживает граф данных (@graph) для сложных структур
